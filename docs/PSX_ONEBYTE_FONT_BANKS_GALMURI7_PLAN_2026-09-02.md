# PS1 1바이트 소형 UI 폰트 / Galmuri7 적용 계획 (2026-09-02)

## 결론

캐릭터 정보창의 `LVL`, `AGE`, `STR` 등 초소형 1바이트 UI는 `OFONT.MMT`를 직접 쓰는 경로로 단정할 수 없다. PSX.EXE의 실제 1바이트 글자 렌더러를 역추적하면 `FONT.MMT`의 renderer glyph 뱅크를 직접 선택한다.

따라서 소형 한국어 UI는 **FONT.MMT 내 전용 1바이트 뱅크 + Galmuri7** 방식으로 설계한다. `OFONT.MMT`는 역할이 별도로 확인될 때까지 수정하지 않는다.

## 확인된 1바이트 렌더러

PSX.EXE runtime `0x80074D84`의 핵심 동작:

- 문자열은 1바이트 단위로 소비한다.
- style/bank 인수는 `0..7` 범위로 제한된다.
- 한 뱅크는 176 renderer glyph 단위다.
- 기본 계산은 다음 형태다.

```text
renderer_glyph = adjusted_byte + (176 * bank)
```

상위 비트가 켜진 1바이트 문자는 기존 일본어 반각 문자 처리를 위해 보정된다. 이 경로와 2바이트 DBCS renderer(`0x80074F0C`)는 별도다.

## 현재 한국어 코드표와의 충돌

현재 본문용 공용 한국어 코드표는 1,133자를 고슬롯에서 연속 할당한다. 이 상태에서 소형 UI용 뱅크를 임의로 덮으면 본문 한글 글리프와 충돌한다.

소형 한국어 전용 후보 뱅크:

```text
bank 7 = renderer slots 1232..1407 (176 slots)
```

따라서 Galmuri7을 넣기 전에 본문용 DBCS 할당기가 이 범위를 예약할 수 있어야 한다.

## 목표 슬롯 정책

다음 구조를 목표로 한다.

```text
0..351       : 기존 1바이트 ASCII/반각 문자 영역 보존
1232..1407   : Galmuri7 소형 한국어 전용 bank 7 예약
나머지       : 본문/대화/아이템/몬스터용 Galmuri11 DBCS
```

`0..351`과 `1232..1407`을 제외해도 1,520개의 renderer slot이 남으므로 현재 한국어 1,133자를 수용할 수 있다.

## 적용 순서

1. 본문 DBCS 할당기에 반복 가능한 `--reserve-range FIRST:LAST` 기능 추가.
2. 공용 MSG/FONT/SCENARIO 매핑을 예약 범위를 피해 다시 생성.
3. CI에서 본문 한국어 매핑과 소형 bank 7의 겹침이 0인지 검증.
4. Galmuri7 BDF에서 고정 UI에 필요한 한글만 추출.
5. bank 7에 소형 한글 글리프 패킹.
6. `레벨`, `힘`, `민첩` 같은 고정폭 UI 호출부만 bank 7을 사용하도록 변경.
7. 본문/아이템명 등 가변 문자열은 기존 2바이트 DBCS + Galmuri11 경로를 유지.

## 주의

아이템명처럼 수백 자가 필요한 가변 문자열을 176자짜리 1바이트 뱅크에 넣지 않는다. 소형 Galmuri7 뱅크는 고정 UI 라벨 전용이다.

또한 v9에서처럼 신규 렌더러 호출 규약을 임의로 주입하지 않는다. 가능한 한 기존 PS1 렌더러/래퍼를 재사용하고 실기 검증 후에만 생산 경로에 병합한다.
