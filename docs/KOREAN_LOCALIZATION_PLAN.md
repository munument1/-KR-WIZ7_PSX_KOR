# Wizardry VII PSX 한국어화 작업 계획

## 1. 프로젝트 기준

- 저장소: `munument1/-KR-WIZ7_PSX_KOR`
- 기반 프로젝트: `gertius1/WIZ7_PSX_ENG`
- `main`: 원본 영어패치 추적용. 가급적 직접 수정하지 않는다.
- `korean-localization`: 한국어화 개발 브랜치.
- 게임 본체, PS1 디스크 이미지, 추출된 저작권 데이터는 저장소에 포함하지 않는다.
- 최종 배포는 원본 디스크 이미지에 적용하는 패치 형태를 기본으로 한다.

## 2. 현재 확인된 원본 영어패치 구조

원본 프로젝트는 단순 번역 텍스트가 아니라 PS1판의 텍스트 구조와 실행 파일을 상당 부분 분석해 둔 상태다.

### 게임 본문

- `MSGHDR_indexText.txt`
  - 영어 PC판 텍스트를 PS1판 구조에 맞춰 수정한 최종 작업 텍스트.
- `CDS/D/MSGJ.DBS`
  - 게임 내 문자열 본문. Huffman 압축.
- `CDS/D/MSGJ.HDR`
  - 본문 인덱스와 서브인덱스 위치 정보.
- `CDS/D/MISCJ.HDR`
  - Huffman 트리.
- `Wiz7_Patching_Utilities`
  - HDR/DBS 추출, 비교, 재생성에 쓰인 C++/JUCE 도구 소스.
- `writeDBSFromCSV(bool JAP)`
  - 텍스트 파일을 다시 `MSGJ.HDR` / `MSGJ.DBS`로 만드는 핵심 함수.

### 대화 키워드

- `CDS/D/TALK.SCR`
  - NPC 대화 질문/토픽과 응답 인덱스 연결.
- `TALK.txt`
  - 영어패치 작업용 텍스트 표현.
- 관련 함수:
  - `parseTalkScr()`
  - `writeTalkScr()`

### 문자 표시

- `CDS/D/ZENKAKU.TBL`
  - 원본 분석 문서에서 16-bit 폰트/문자 테이블로 확인됨.
- `FUN_ASCIItoZENKAKU` (`PSX.EXE` 런타임 주소 `0x8006CB80`)
  - ASCII 인덱스를 2바이트 문자 값으로 변환.
- 영어패치에서는 `PSX.EXE` 파일 오프셋 `0x5D3F8`을 `0x60 -> 0x70`으로 변경하여 영문 소문자 표시 범위를 확장함.

### 줄바꿈

일본판은 공백마다 줄바꿈하는 동작이 있었고 영어패치에서 이를 수정했다.

- 인젝션 코드: `Assembler Injects/LineBreak16char_1.2_final.txt`
- 삽입 위치: `PSX.EXE` 끝쪽 `0xBA000`
- 기존 함수 호출을 `0x8005C828`에서 새 코드로 우회.
- 현재 로직은 약 16문자를 한 줄 기준으로 처리함.

한국어에서는 글자 폭과 조사/어절 구조 때문에 이 코드를 그대로 쓰지 않고 다시 조정할 가능성이 높다.

## 3. 가장 중요한 기술적 문제

### A. 한글 글리프가 어디에서 렌더링되는지 확정

저장소에는 게임 본체의 `ZENKAKU.TBL`이나 실제 폰트 리소스가 포함되어 있지 않으므로, 우선 사용자가 보유한 원본 게임에서 다음 파일을 직접 추출해 조사해야 한다.

- `PSX.EXE`
- `CDS/D/ZENKAKU.TBL`
- 필요 시 관련 폰트/그래픽 파일

확인할 사항:

1. `ZENKAKU.TBL`이 실제 비트맵 글꼴인지 문자 코드 매핑 테이블인지.
2. 일본어 글리프가 게임 파일에 들어 있는지 PS1 BIOS/JIS 글꼴을 호출하는지.
3. 한글 글리프를 새로 삽입할 공간이 있는지.
4. 일본어 문자 슬롯을 한국어 전용 슬롯으로 재사용할 수 있는지.

### B. 현재 Huffman 인코더의 문자 수 제한

`Wiz7_Patching_Utilities/Source/HuffmanTable.cpp`의 영어용 테이블은 `nrOfHuffmanChars = 122`로 고정되어 있고 ASCII/제어코드 위주다.

따라서 UTF-8 한글을 그대로 넣는 방식은 불가능하다.

후보 전략:

1. **한국어 전용 1바이트 문자 코드 체계**
   - 실제 번역에 필요한 완성형 글자만 추려 코드페이지를 생성.
   - 글자 수가 1바이트 공간을 초과하면 불가.

2. **2바이트 한글 코드 확장**
   - 런타임 디코더/문자 변환 루틴을 수정해 2바이트 토큰을 지원.
   - 구현 난이도는 높지만 전체 한국어 지원에는 가장 정석적.

3. **조합형 렌더링**
   - 초성/중성/종성을 조합해 한 글자를 렌더링.
   - 저장 공간은 적게 들 수 있으나 PS1 렌더러 수정 난이도가 매우 높음.

4. **일본어 기존 문자 슬롯 재활용 + 제한 글자 사전**
   - 먼저 소수 한글 글리프만 넣어 POC를 만들 때 유용.
   - 최종 방식으로 확정하지 않는다.

초기에는 4번으로 "한글 한 글자 출력"을 먼저 성공시킨 뒤, 실제 문자 수와 렌더링 구조를 보고 1~3 중 최종 방식을 결정한다.

## 4. 단계별 작업

### Phase 0 — 원본 영어패치 재현

목표: 원본 개발자가 했던 빌드 과정을 우리 환경에서 다시 실행할 수 있게 만든다.

- 원본 일본판 디스크를 사용자가 직접 준비.
- 지원 원본 BIN 체크섬:
  - CRC32: `BAB5DD73`
  - MD5: `188D3EE5A2A2242A719F290EA595E5EC`
- 영어패치의 `MSGJ.HDR`, `MSGJ.DBS`, `TALK.SCR` 재생성 과정을 재현.
- 원본 영어 xdelta 결과와 기능적으로 동일하게 실행되는지 확인.

성공 기준:

- 수정한 임의 영문 문자열 1개가 게임 안에서 정상 출력.
- 세이브/로드 및 NPC 대화에 치명적 문제가 없음.

### Phase 1 — 한글 글리프 POC

목표: 번역 전체를 넣기 전에 화면에 한글 한 글자라도 확실히 출력한다.

권장 테스트 문자열:

- `가`
- `한`
- `글`
- 최종 POC: `한글`

작업:

- `ZENKAKU.TBL` 및 실제 글리프 원본 분석.
- 기존 일본어 문자 슬롯 하나를 테스트용 한글 글리프로 교체.
- 해당 슬롯을 본문 문자열에서 호출.
- 필요한 경우 `FUN_ASCIItoZENKAKU` 또는 그 후단 렌더링 함수 패치.

성공 기준:

- DuckStation에서 `한글` 중 최소 1글자가 안정적으로 표시됨.
- 같은 글자를 여러 화면에서 호출해도 깨지지 않음.

### Phase 2 — 한국어 문자 인코딩 설계

목표: 실제 전체 번역을 수용할 문자 체계를 확정한다.

- DOS판 한국어 번역 데이터에서 사용된 한글 완성형 글자 집합을 추출.
- 전체 고유 한글 글자 수 계산.
- PSX판에서 실제 필요한 추가 문자까지 합산.
- Huffman 트리와 디코더를 한국어용으로 재생성할 수 있는지 검증.
- 제어코드(`=xxx`, 특수 문자 등)는 원본과 완전히 분리하여 보존.

성공 기준:

- 임의의 한국어 100자 이상 문장을 `MSGJ.DBS`에 넣고 정상 디코딩/표시.
- 제어코드가 섞인 문자열에서도 진행 플래그가 정상 작동.

### Phase 3 — 본문 번역 이식

목표: 기존 Wizardry VII DOS 한국어 번역을 PSX 영어 텍스트와 대응시킨다.

원칙:

- PSX판 전용 대사/메뉴/질문 구조는 PSX 영어패치를 기준으로 유지.
- DOS 번역은 의미 번역 자산으로 사용하되 인덱스를 기계적으로 동일시하지 않는다.
- `MSGHDR_indexText.txt`의 main/sub index 구조와 function code를 절대 훼손하지 않는다.

검증:

- `compareFunctionCodes()` 계열 검사 활용.
- NPC별 진행 플래그/질문 메뉴 검사.
- 0x400 데이터 블록 경계와 `MSGJ.DBS` 최대 크기 `0x3FFFF` 감시.

### Phase 4 — UI / 이미지 / 영상 자막

- 메뉴와 이미지 텍스트 한글화.
- `CDS/M/OPEN.TXT` 인트로 영상 자막 처리.
- 글자 폭 때문에 잘리는 메뉴 창 조사.
- 필요 시 원본 영어패치 TODO였던 메뉴 창 크기 확장까지 진행.

### Phase 5 — 줄바꿈 및 가독성

영어판 16자 로직은 한글에 그대로 맞지 않을 수 있다.

- 고정 글자 수 기준과 실제 픽셀 폭 기준을 비교.
- 한국어 어절 단위 줄바꿈 구현 검토.
- 특수 제어코드를 일반 문자로 세지 않도록 보장.
- 스토리 창, NPC 대화 창, 작은 UI 창을 따로 테스트.

### Phase 6 — 전체 QA

최소 검사 범위:

- 신규 캐릭터 생성
- 전투
- 아이템/장비 정보
- 주문
- NPC 질문/응답
- 주요 세력 퀘스트
- 엔딩
- 세이브/로드
- 인트로 및 주요 이벤트

원본 영어패치에 이미 알려진 버그가 있으므로, 한국어화로 새로 생긴 문제와 원본 문제를 분리해 기록한다.

## 5. 배포 계획

### 기본 배포

게임 본체를 포함하지 않는 `xdelta` 패치를 배포한다.

사용 흐름:

`정품 일본판 디스크 -> 사용자 직접 BIN/CUE 덤프 -> 체크섬 확인 -> 한국어 xdelta 적용 -> DuckStation 실행`

### CHD 지원

최종 단계에서 보조 패처를 만들 수 있다.

`CHD 입력 -> 임시 BIN/CUE 추출 -> 체크섬 확인 -> xdelta 적용 -> 한국어 CHD 재생성`

CHD 자체를 기준으로 xdelta를 만들지 않는다. CHD는 생성 도구/버전/압축 조건에 따라 파일 바이트가 달라질 수 있기 때문이다.

## 6. 저장소에 넣지 않을 것

- 원본 또는 패치된 PS1 `BIN/CUE`
- `CHD`, `ISO` 등 게임 디스크 이미지
- 원본에서 추출한 전체 `PSX.EXE`
- 원본 `CDS/` 데이터 트리
- ROM/디스크 이미지 다운로드 링크

저장소에는 아래만 둔다.

- 소스 코드
- 분석 문서
- 한국어 번역 데이터
- 새로 제작한 폰트/변환 데이터
- xdelta 등 차이 패치
- 사용자가 직접 준비한 원본을 처리하는 스크립트/패처

## 7. 당장 다음 작업

1. 사용자가 보유한 PS1 원본을 BIN/CUE 또는 CHD 형태로 준비한다.
2. CHD라면 `chdman extractcd`로 BIN/CUE를 만든다.
3. BIN의 MD5/CRC32를 영어패치 기준과 비교한다.
4. 원본에서 `PSX.EXE`, `CDS/D/ZENKAKU.TBL`, `CDS/D/MISCJ.HDR`, `MSGJ.HDR`, `MSGJ.DBS`를 작업 디렉터리로 추출한다.
5. 영어패치 빌드 파이프라인을 재현한다.
6. `ZENKAKU.TBL`과 글리프 렌더링 경로를 분석한다.
7. `한` 또는 `가` 한 글자 출력 POC를 만든다.

## 8. 현재 판단

이 프로젝트에서 가장 큰 리스크는 번역량이 아니라 **한글 문자 렌더링과 인코딩**이다.

반대로 본문 인덱스/Huffman 재패킹/NPC function code/줄바꿈/실행 파일 인젝션은 원본 영어패치 제작자가 이미 상당 부분 해결해 두었다. 따라서 한글 한 글자 출력과 한국어 문자 코드 체계만 확보하면 이후 작업은 기존 DOS판 번역 자산을 이용해 빠르게 진행할 가능성이 있다.
